# #314 reasoning-quality eval: thinking replay OFF vs ON (2026-10-08)

The follow-up to #405, designed with `home` and run on Vertex (`gke-claude-dev`, `us`) with the owner's approval.
#405 found replay only added cache writes on a workload that rarely thought. This eval asks whether replay changes
**success** on tasks where the deciding information lives in thinking, at high effort, and what it does to cost
there.

**Every cell is n = 3 reps per arm. Read the cost differences as directional.** Where per-rep ranges overlap, this
README says so.

## Headline

1. **Success: no separation found. Both arms solved every task in every run (36/36 runs each).** That holds for 7-
   and 9-stop shortest tours, 5×5 and 6×6 Latin squares with two valid completions, and a hidden-commitment record
   task, gagged and not, at high and default effort. Fisher p = 1.0 everywhere. Opus 5.5 with replay OFF re-derives
   its plan correctly each round. **Under the agreed go/no-go rule the full run was not done**: OFF never failed, so
   no task can separate the arms.
2. **Cost at high effort: ON is cheaper, but by how much depends on whether the model writes its plan down.**
   - **Gagged** (the model may not state the plan, so replay is its only memory): ON is **27-56% cheaper** and uses
     **62-73% less output**. The ranges don't overlap on the XL tasks. With replay OFF the model re-derives the whole
     plan in thinking on every round (1,000-1,600 output tokens per round); with it ON the model thinks once and
     carries the plan.
   - **No gag** (normal prompting, as Iris normally runs): ON is **11-12% cheaper on average with 46-56% less
     output**, but at n = 3 the **cost ranges overlap** (route OFF $0.129-0.206 vs ON $0.126-0.171; Latin OFF
     $0.194-0.276 vs ON $0.179-0.256). Without the gag, OFF re-derives only in the first 2-3 rounds; after that the
     plan is in its own visible text and each round costs about 81 output tokens.
   - So most of the gagged saving comes from the gag. In normal use the saving is real in output tokens (about half)
     and plausible but **not established** in dollars.
3. **At default effort** (what Iris sends today), the records task shows the same direction (ON about 40% less
   output, cost about 12% lower) and the same ceiling on success.
4. **Correctness:** no response in any run carried a non-empty `input_transformations`.

**Read for the default setting:** nothing here argues for turning replay ON by default. It doesn't change success
on these tasks, and in normal prompting its cost effect is within noise. The one consistent effect is the
output-token saving whenever the model thinks hard across rounds, which supports pairing replay with a future
per-tier effort setting ("high effort + replay") rather than enabling it alone. Showing an effect on success would
need tasks harder than these for Opus 5.5 at high effort, and n ≫ 3.

## Setup

- **One binary**, main at `109ed3e`, plus `measurement-perf-overrides.patch`. It's perf-only and is **not** merged
  (iris work is paused for the restructure):
  - `IRIS_PERF_SEED_JSON` targets Anthropic on Vertex through the run's volatile settings copy (as in #405);
  - `IRIS_PERF_REPLAY=0` is the replay switch, the same condition the planned Setting will flip;
  - `IRIS_PERF_EFFORT=high` sets `output_config.effort`, which is outside the bound prefix.
- **Model:** claude-opus-5-5 on Vertex `us`. Fable wasn't run: the plan was Fable only if Opus separated.
- **Arms** alternate order by rep. Perf real lane, rung 4, `run_command` sandboxed. Each task is a single turn of
  many tool rounds, one action per reply.
- **Tasks** are in `tasks/`, generated by `generate.py` with fixed seeds and known answers in `truth*.json`:
  - **route** (7 stops, opt 134 / XL 9 stops, opt 144): two optimal tours (four counting direction) and several
    within 2. Appends one stop per reply. Passes if the stops form a permutation from A whose round trip equals the
    optimum.
  - **latin** (5×5 with 11 givens / XL 6×6 with 17): exactly 2 valid completions. Fills one cell per reply. Passes
    if the result is a valid square that respects the givens and never overwrites a cell.
  - **records:** 12 records, exactly one satisfies a 3-clause arithmetic criterion, and 4 satisfy two. Four
    unrelated commands come first, then `echo ID > out/answer.txt`. Passes if the answer is LARCH.
  - **gag** = "do not explain or write the plan, choice or future steps; reply with the tool call only".
    **nogag** = the same prompt without it.
- **Scoring:** `check.py` rebuilds what the model *did* from the `run_command` arguments in each record:
  `python3 check.py tasks records`.

## Reproduce

Apply the patch to main, `swift build -c release`, copy `tasks/*.json` into `perf/prompts/314-eval/` and the
`314-eval-*.json` suites into `perf/suites/`, then per run:

```sh
IRIS_PERF_SEED_JSON='{"PRIMARY_PROVIDER":"Anthropic","ANTHROPIC_AUTH_MODE":"Vertex AI (ADC)","ANTHROPIC_VERTEX_PROJECT":"<project>","ANTHROPIC_VERTEX_LOCATION":"us","ANTHROPIC_MODEL_MEDIUM":"claude-opus-5-5"}' \
IRIS_PERF_REPLAY=0|1 IRIS_PERF_EFFORT=high IRIS_PERF_BASE_PRICE_PER_MTOK=4 \
  .build/release/iris --perf run perf/suites/314-eval-high.json --out <dir>/OFF-high-r1
```
