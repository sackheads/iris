# Token tracking & diagnostics

Moved from the feature tour ([docs/features.md](features.md)), word for word (#534).

Real-time visibility into prompt/candidate tokens, plus a dedicated Diagnostics UI that charts LLM latency metrics across different model tiers and Vibecop requests. The prompt count folds in cache reads and writes, and for Anthropic (which never sends a total) the total is filled from prompt + output, so conversations show real, non-zero figures and the sidebar's token section appears. The job budgets count weighted tokens, not raw ones. Iris's own conversation, and job runs when a job fires more often than hourly, hold the Anthropic prompt cache for an hour instead of five minutes; OpenAI requests carry a `prompt_cache_key`: the conversation id for a chat, and for job runs, subagents and evaluators a short hash of the profile and declared tools, so runs that share a prompt prefix are routed to the same cache. An easy-tier prompt under 4,096 tokens on Haiku, or under 1,024 on OpenAI, never caches, so it is always charged as uncached. On Claude Opus 5.5, Fable 5.1 and Sonnet 5.5, on the default `api.anthropic.com` route or on Vertex AI, Iris sends Anthropic's thinking-binding beta header and records the response's `input_transformations` on each model call, with a console line whenever thinking was dropped or would have been. On Claude models, Iris can replay a turn's own thinking blocks back to the model across tool-call rounds so it keeps its reasoning across tool calls instead of starting cold each round — "Replay Claude's thinking within a turn" in Settings, **off by default**. A paid measurement (PR #405) found replay costs about 18% more per task on Opus 5.5, with no fewer rounds, and both arms succeeded every time, so whether it improves reasoning quality is still unmeasured; hence the default. With the setting off, every request goes out with no thinking blocks, on any Claude model, exactly as on a non-Anthropic provider — none of the replay mechanics below run. The beta header and `input_transformations` recording described above happen on every Claude call regardless of this setting, since they are free and diagnostic, and Iris still keeps each reply's content blocks exactly as they arrived in conversation history either way. With the setting on: a `BeforeModel` or `AfterModel` hook that rewrites what was sent, a `PreCompress` hook that changes history, or a mid-turn history edit each keep every thinking block produced before the change out of the turn's later requests, and replay resumes with the next reply. A `BeforeModel` hook that rewrites identically every round is not a change and keeps replay going; an `AfterModel` rewrite is always one, since the rewritten reply keeps no blocks, so a hook that rewrites every reply means no replay in that turn. Older turns always go out without thinking. A custom Anthropic base URL gets no beta header, since a gateway in front of it may reject an `anthropic-beta` value it does not recognize. When replay is on and Anthropic rejects a replayed thinking block as "bound to a different conversation", Iris retries that call once with the beta header and `drop_block` (which also asks for adaptive thinking), on any model or route including a custom base URL, and never again sends that turn's thinking blocks up to and including the retry's own reply; replay resumes with the next reply. Once that retry succeeds, the conversation keeps `drop_block` and sends it on every later request, across restarts, but only where the beta header is sent (those three models, on the default route or Vertex) — for Sonnet 5.5 specifically, that also keeps it on adaptive thinking for the rest of that conversation, since the binding field only travels inside an adaptive thinking object; on another model, an unknown one or a custom base URL it is not sent, and a binding rejection there gets the same one-off retry.
