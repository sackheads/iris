# Anthropic thinking replay and an append-only history

Status: **proposed** (2026-10-06). Implements #314. The design comes from the research brief of the same date (no API calls were made for it). The owner ruled on its open questions on 2026-10-06; those rulings are marked **(ruling)** below and bind this spec.

Iris throws away every thinking block Anthropic returns. On Opus 5.5 and Fable 5.1, thinking is always on and the signature carries the reasoning, so the model loses its own reasoning every time a tool result comes back. Replaying the blocks is only safe if the request prefix the signature was bound to is sent again byte-for-byte, and today Iris rebuilds that prefix in several places. This spec does it in two phases:

- **Phase 1** replays thinking within the current turn only. It is safe on main as it stands, on every model and account.
- **Phase 2** replays every block, after the PRs that make the history append-only have landed.

## Facts this rests on

Doc paths are relative to the bundled `claude-api/shared/` directory: PTM = `preserved-thinking-migration.md`, CAUSES = `preserved-thinking-migration/causes.md`, MM = `model-migration.md`, PC = `prompt-caching.md`, PA = `platform-availability.md`, TUC = `tool-use-concepts.md`. Where the docs and the issue differ, the docs win.

- **Which models check.** "Claude Fable 5.1 and Claude Opus 5.5 today" (PTM:7). Mythos 5.1 "does not run this check" (MM:1605). Thinking is always on for both: Opus 5.5 rejects `{"type": "disabled"}` and `{"type": "enabled", ...}` "at every effort level" (MM:1874), and Fable 5.1 accepts only adaptive (MM:1322). Iris's tier defaults (`ConfigManager.swift:432-434`) include neither, so the check applies only once a user picks `claude-opus-5-5` or `claude-fable-5-1`.
- **What a signature binds.** "the top-level `system` prompt, the set of `tools`, and every message before the block" plus the producing model (PTM:7), "plus a chain to the previous thinking block" (MM:1609). It is invalidated by editing, reordering or removing an earlier turn; "Injecting per-request text into an earlier turn ... that you remove or rebuild on the next request"; "Rebuilding the top-level `system` prompt or `tools` array"; removing a block "from anywhere other than the start of the run"; and different bytes behind an image URL (MM:1611-1617).
- **What it does not bind.** `cache_control`, "reordering the `tools` array", and a model switch are Tier 0 (PTM:24). Tools are "compared as a name-keyed set", and a `defer_loading` tool counts only once something names it (PTM:88). Outside the prefix: `max_tokens`, `tool_choice`, `output_config` (effort included), and "the `thinking` configuration itself" (CAUSES:74). "Adding or removing a plain tool" is `tool_set_changed`, and changing a description is `tool_schema_changed` (CAUSES:21).
- **The 400.** The check is "enforced by default for accounts created on or after August 31, 2026, 00:00 UTC". Older accounts are enforced only when "a request ... sets `prefix_mismatch_behavior`" (PTM:40, MM:1609). The error reads ``Invalid `signature` in `thinking` block. The block is bound to a different conversation.`` (MM:1624). "Retrying the same body fails the same way; the token-counting endpoint runs the same check" (MM:1621).
- **`drop_block`.** Header `anthropic-beta: thinking-binding-controls-2026-08-01`; body `"thinking": {"type": "adaptive", "block_binding": {"prefix_mismatch_behavior": "drop_block"}}` (MM:1632-1638). It "drops the first mismatched block **and every thinking block after it**", for that request only (MM:1641, 1649). The field without the header is a 400 ending in `block_binding: Extra inputs are not permitted`. "The header without the field does **not** turn enforcement on" for an older account; mismatched blocks still reach the model, listed as `thinking_mismatch_allowed` (PTM:134). "copying the field into production lifts the exemption on every request that carries it" (PTM:182). Documented recovery: "retry once with the beta header and `prefix_mismatch_behavior: "drop_block"`, and store that choice with the session so every later request sends it too, including after a restart" (CAUSES:93). Yet "`drop_block` ... is not a fix" (PTM:36).
- **`input_transformations`.** A top-level array beside `usage`, `[]` when nothing happened, present on every response when the header is sent. Entries: `{"type": "thinking_dropped", "path": ..., "reason": "prefix_binding_mismatch"}`, reason `model_binding_mismatch`, and `thinking_mismatch_allowed`. Streaming, it arrives in `message_start`, and again in the final `message_delta` only after a mid-stream server-side model fallback. Ignore unknown types and reasons (PTM:145). Count a break once per conversation, keyed by `signature` (PTM:168). The `anthropic-thinking-prefix-mismatch` header: "Use it if present; never depend on it" (PTM:146).
- **`clear_at`.** Beta `mid-conversation-system-clear-at-2026-08-21`; `{"role": "system", "clear_at": "next_user_message", "content": "..."}`; "a cleared message costs no input tokens" (MM:1705, 1719). Text-only, "takes no `cache_control` (put the breakpoint on the preceding user turn)", and "one followed directly by another `user` message is a 400"; "a `tool_result`-only user message counts as the next user message" (MM:1724). It "Must follow a `role: "user"` message ... cannot be `messages[0]`" (PC:81). Mid-conversation system messages run on "Claude Opus 5, Claude Opus 5.5, Claude Opus 4.8, Claude Fable 5, Claude Fable 5.1, Claude Mythos 5, and Claude Mythos 5.1; no beta header. Not available on Claude Sonnet 5" (PC:67); otherwise "`role 'system' is not supported on this model`" (PC:81). On Opus 5.5 `clear_at` is "a limited beta" (MM:1941).
- **Tool changes.** Beta `mid-conversation-tool-changes-2026-07-01`, the PC:67 list minus Sonnet 5 (TUC:285). "A tool you plan to add must already be declared in `tools[]` with `"defer_loading": True`" (TUC:301); announce it with a `tool_addition` block, "never append a regular tool"; withdraw with `tool_removal` and leave the entry (PTM:197). A `tool_removal` "must sit immediately before an assistant message, or last in messages" (TUC:290). A same-name change has no append-only form except `inline-tools-2026-09-15`, "Claude API only" (CAUSES:59). A deferred, unreferenced tool is "not loaded into the model's context" (TUC:301).
- **Effort and display.** Opus 5.5's API default effort is `medium` (MM:2007); Fable 5.1's is `high` (MM:1758). Effort is `output_config: {"effort": ...}`; sending the default "is equivalent to omitting it" (PC:240); changing it invalidates the prompt cache (MM:2010) but not thinking (CAUSES:74). `display` defaults to `"omitted"` (blocks return `thinking: ""`; MM:1348). `"updates"` needs `thinking-display-updates-2026-08-18` on "Claude Fable 5.1, Claude Mythos 5.1, Claude Fable 5, Claude Opus 5.5" (PA:48). On Opus 5.5 "text between tool calls comes back in thinking blocks" (MM:1985). Replay blocks "exactly as received - including blocks whose `thinking` text is empty" (MM:1350). `max_tokens` covers thinking too; "64K has worked well" (MM:1884).
- **Cost.** On the PC:240 models "previous-turn thinking blocks are preserved by default", so replay keeps the cache valid. Replayed blocks are "counted in input tokens" (CAUSES:13); dropped blocks are "not billed" (PTM:145), but "A dropped block changes the cached prefix from its position onward" (MM:1599). Cache reads are 0.05x on Opus 5.5 and 0.025x on Fable 5.1, "so ... a miss costs relatively more" (MM:2023, 1678).
- **Model switches.** "the API drops what the target can't read, unbilled" (MM:1601). Opus 5.5 blocks are read by Fable 5.1 and Mythos 5.1 on the Claude API (MM:1940); Fable 5.1 blocks only by Mythos 5.1 (MM:1597).
- **Vertex.** The same beta names go in the `anthropic-beta` header (MM:1609, PA:49). `clear_at`, tool changes, display updates and per-message effort are beta there (PA:45-48); `inline-tools` is not offered. The probe "cannot replay captures taken on ... Vertex AI" (PTM:53).
- **In Iris, within one turn the prefix is already append-only.** System and tools are fixed per turn (`request.tools` is set once, `iris.swift:1958`), the turn context sits on the same entry in every round, and images are stripped only at turn end. Every break is at a turn boundary. Phase 1 relies on this.

## 0. Decided

Each decision names its default, why, and the cost if wrong. **[P1]** lands in Phase 1, **[P2]** in Phase 2, **[any]** is independent of the phases.

1. **Store the assistant content array as received. [P1]** `Content.anthropicBlocks: String?` holds the JSON array of the reply's blocks, assembled by `AnthropicStreamMapper` per block index (text, `thinking_delta`, `signature_delta`, `partial_json` bytes, `redacted_thinking.data`), carried through a new `LLMStreamEvent` case and `StreamAssembler` so the non-stream path keeps it, and set on the `Content` at `iris.swift:2131`. `AnthropicClient` echoes `anthropicBlocks` when present and builds from `parts` otherwise. `parts` stays for the UI, hooks and other providers.
   - An incomplete block (a stream that died mid-thinking) is never stored; only `partial` text is, as today.
   - When the AfterModel hook changed the reply, drop its stored blocks. That is a trailing drop, which is allowed (CAUSES:77).
   - Invariant 1: `Content.init(from:)` is custom (`Models.swift:234-238`), so the field gets `decodeIfPresent` and a `CodingKeys` case. History rows are whole-`Content` JSON, so no column. `LLMClient.encodeGeminiBody` must strip the field. `read_conversation` and search ignore signatures.
   - *Why:* `StreamAssembler.response()` merges every text block into one part and appends the calls after it, so order and boundaries are lost, and progress blocks sit between `text` and `tool_use` on Opus 5.5 (MM:1985). Rebuilding from parts fails the chain. Storing wire bytes avoids a per-block domain model. *Cost if wrong:* history rows grow by the signature bytes.
2. **Replay rules. Phase 1 [P1]:** replay thinking only from assistant messages after the current turn's entry; older turns go out without thinking, deterministically. Removing a leading run is allowed (CAUSES:77), and each turn's blocks are the contiguous tail. **Phase 2 [P2]:** replay every block, on per model: on for `runsPrefixCheck` models once PRs 3-5 land, and on for the rest because nothing binds there. **Both:** never edit, reorder or thin the middle; send blocks on a model switch and let the API drop what it must; once a strip is recorded, keep it stripped (PTM:211). *Why (ruling 1):* Phase 1 fixes the headline (reasoning lost when the tool result returns) with no beta and no 400 risk. Phase 2 matters for goal loops, where each reprompt is a new turn. *Cost if wrong:* Phase 1 alone loses cross-turn reasoning and its cache reads.
3. **One `AnthropicCapabilities` table. [P1]** Keyed on the model id after `vertexModelID` normalization, it owns `runsPrefixCheck`, `supportsSystemMessages` (the PC:67 list), `supportsToolChanges` (TUC:285), effort, display updates and `max_tokens`. Unknown ids count as `runsPrefixCheck` with no system messages: header sent, field unset, 5a's turn context kept. *Why:* one place to update when the model list moves. *Cost if wrong:* an unknown id that does support system messages runs the fallback paths.
4. **`max_tokens` per model. [P1]** Replace the hardcoded 4096 (`AnthropicClient.swift:177`) with a per-model value in the 32-64K range from the table. *Why:* with thinking always on, 4096 must cover thinking plus the reply (MM:1884). The issue does not mention this. *Cost if wrong:* `max_tokens` is outside the prefix, so only a longer worst-case reply.
5. **Beta headers on both transports. [P1, grows]** Iris sends no `anthropic-beta` today (`AnthropicClient.swift:255-262`). Each beta is sent only to models the table says support it: `thinking-binding-controls-2026-08-01` (P1), `thinking-display-updates-2026-08-18` (decision 13), `mid-conversation-system-clear-at-2026-08-21` and `mid-conversation-tool-changes-2026-07-01` (P2). Never `inline-tools-2026-09-15`. *Cost if wrong:* a beta the model rejects is a 400 on every request, caught by the self-test in §2.
6. **Binding policy (ruling 2). [P1 header, P2 retry]** On `runsPrefixCheck` models, always send `thinking-binding-controls-2026-08-01` and leave `prefix_mismatch_behavior` unset. On a 400 containing "bound to a different conversation", retry once with `drop_block` before any stream event is yielded (the TTL-retry shape at `AnthropicClient.swift:288-306`), and persist `prefixMismatchBehavior = "drop_block"` on the conversation (`decodeIfPresent` plus a `conversations` column) so every later request sends it, across restarts (CAUSES:93). `"error"` is used only in CI, on fake-lane replays. *Why:* setting the field everywhere lifts the old-account exemption (PTM:182) and loses reasoning that unset would keep. *Cost if wrong:* a new account pays one failed request per broken conversation, then runs with `drop_block` for the rest of it.
7. **Log `input_transformations`. [P1, record-only]** Parse it from `message_start`, the final `message_delta`, and the non-stream top level; ignore unknown types and reasons. Count new `prefix_binding_mismatch`, `model_binding_mismatch` and `thinking_mismatch_allowed` entries per conversation, keyed by `signature`, and record them on `ModelCallRecord` (`decodeIfPresent`; perf JSON is persisted). Print the diagnosis header if present. The first break per conversation goes to the console log; no user pill. *Why:* it is the only production signal, and the only one on Vertex. *Cost if wrong:* log noise.
8. **Turn context moves to `clear_at` (ruling 5). [P2]** On `supportsSystemMessages` models, the 5a block is no longer inserted into the turn's entry. Instead `{"role":"system","clear_at":"next_user_message","content":<rendered>}` is appended after the entry and after each `tool_result` message of the turn, **every round**. Each copy is persisted with the assistant reply that follows it, as `Content(role: "system")` with `systemClearAt` (`decodeIfPresent`). A copy whose round failed is never persisted, because a later steer would follow it directly (the 400 at MM:1724).
   - *Fallback* on Sonnet 5, Haiku and unknown ids: keep 5a as is. Cleared copies are omitted and the newest copy is inlined as 5a's leading part, a pure function of history.
   - *Marker effects:* `TurnRequest`'s anchors and byte check go unused on this path. Marker (b), the end of turn k-2, stops being the read point; with nothing removed, turn k-1's rounds become readable. Markers skip `role: "system"` messages (no `cache_control`, PC:83) and land on the preceding user turn.
   - *Other encoders:* the Gemini and OpenAI encoders must filter `role == "system"`. Today both map any non-`model` role to `user` (`AnthropicClient.swift:68`, `OpenAIClient.swift:23`), which would send the context as a user message.
   - *Why:* inserting and then dropping the block is `reminder_stripped` (CAUSES:45) and invalidates every thinking block of turn k at turn k+1. Every round follows the doc pattern; the perf arm (§2) decides whether once per turn is enough. *Cost if wrong:* the live copy renders uncached every round, where 5a cached it from round 2.
9. **Freeze the system prompt per conversation (ruling 3). [P2]** On `runsPrefixCheck` models that support system messages (Opus 5.5 and Fable 5.1 today), freeze the rendered system text at first send as `Conversation.frozenSystemPrompt` (`decodeIfPresent` plus a column, as `upsertMetadata` at `ConversationStore.swift:745-760` needs) and send those bytes for the rest of the conversation. A change to SOUL, USER.md, AGENTS.md, skills or rules appends one `role: "system"` delta message naming what changed, with the new section text. Declared, logged boundaries: a new conversation, rotation, and an app upgrade that changes SYSTEM.md. *Why:* the prompt is re-rendered by the model's own tools (`update_soul`, skill CRUD, `SkillCurator`), by commands, and by any USER.md or AGENTS.md mtime change, through one engine-wide cache, so an edit in one conversation re-renders every conversation's prefix. *Cost if wrong:* one logged break per upgrade, against running stale steering forever in the pinned conversation.
10. **Images (ruling 4). [P2]** On `runsPrefixCheck` models, images are kept in history, not stripped, and downscaled at ingestion (`AttachmentProcessor.swift` has none today), the only option that "loses nothing" (PTM:203). Elsewhere `stripInlineDataFromHistory` stays. *Why:* stripping is `media_stripped`, and costs every later turn's reasoning on each image turn; pasted screenshots are common. *Cost if wrong:* images are re-read from cache on every later turn.
11. **Tools via `defer_loading` and `tool_addition`; invariant 6 amended. [P2]** On `supportsToolChanges` models, the conversation's first request declares every tool it could ever see: state-gated tools, workflow triggers, and the MCP tools known then. Plain where today's gate is open, `defer_loading: true` otherwise. When a gate first opens, or a trigger turn arrives, append a `role: "system"` `tool_addition` message and leave the tool added (or withdraw it with `tool_removal`, placed as TUC:290 requires). Late MCP or Google tools are appended with `defer_loading` and a `tool_addition`. Descriptions rendered from state (`maxRunsPerHourForWatch`, `searchMemoryDescription(isPinned:)`) are frozen per conversation. Other models keep 5c's behaviour.
    - *Invariant 6 amendment:* "On models that support mid-conversation tool changes, gated tools are declared at the conversation's first request with `defer_loading: true` and announced with `tool_addition` when their gate opens. A deferred, unreferenced tool is not loaded into context (TUC:301), so it costs no prompt tokens." Invariant 9 applies: grep the tool descriptions and `oracleText` that describe gating.
    - *Why:* each first declaration of a plain sticky tool is `tool_set_changed`, triggers are declared and removed within a turn, and a newly sticky tool lands mid-array, a full cache miss (PC:97). *Cost if wrong:* a larger first request; unprompted eagerness on a deferred tool, which §2 checks.
12. **Persist the 5c sticky set. [P2]** StickyTools is "In memory only: a restart re-derives the set" (`StickyTools.swift:5-6`), so after a relaunch the set shrinks, which is a removal. Persist the declared set on `Conversation` (`decodeIfPresent` plus a column), for every provider: the shrink rewrites the history for every provider's prefix cache, not only Anthropic's. This reverses 5c's §0.1 "isn't persisted". *Cost if wrong:* one column.
13. **Effort per tier and `display: "updates"`. [any, after PR 1]** Add `anthropicEffort{Easy,Medium,Hard}` to `ConfigManager`, default "model default" (omitted, which equals the default; PC:240). Send `output_config.effort` only to models with effort, never to `claude-haiku-4-5`. Send a `thinking` object only to adaptive models. On Opus 5.5 and Fable 5.1, send `display: "updates"` with its beta, and stream `thinking_delta` text into the streaming row as a status line, not persisted to `messages` (it is in `anthropicBlocks`). *Why:* it brings back the between-tool narration Opus 5.5 moved into thinking. Effort and `thinking` are outside the prefix (CAUSES:74). *Cost if wrong:* an effort change invalidates the prompt cache (MM:2010).
14. **Vertex and direct. [any]** The same betas in the same header on both. On Vertex, `input_transformations` is the only signal. Measure on the direct API and spot-check Vertex with Iris's own logging. A custom `baseURL` proxy may strip the header or the field, so the self-test runs through that path too.
15. **Tier switches. [P2]** Only a Settings change switches tiers; the main engine is fixed at `.medium` (`AppState.swift:716`). Send the same history. Before the request, strip only what the target rejects: persisted `role: "system"` and `tool_addition` messages for models outside the PC:67 list. Those models run no check, so this is safe, and the stored history is untouched for the return trip. `model_binding_mismatch` drops are reported separately.
16. **Rotation and subagents. [P2]** Rotation is simple compaction, which is fine (MM:1665), but `ConversationRotation.swift:150-163` prepends the summary at index 0; when the history holds a replayable block it appends instead (`first_message_rewritten` otherwise). Subagent and evaluator engines run the same `processInputBody` over their own conversations, so they inherit decisions 1-13 and must persist and replay their own system and `tool_addition` messages (CAUSES:46). Cross-conversation block reuse is impossible by construction.

**Open.**
- Whether `claude-sonnet-5-5` (in `ModelCatalog.swift:61`, not in the bundled docs) runs the check or supports system messages. It falls under "unknown" until verified.
- Unknown ids are `runsPrefixCheck` without system messages, so decision 9's delta has no form there. This spec does not freeze the prompt on them; a re-render is a logged break.
- `clear_at` is "a limited beta" on Opus 5.5 (MM:1941). If the account lacks access, Opus 5.5 needs the fallback; the self-test must detect it.
- On Vertex: whether Fable 5.1 keeps Opus 5.5's blocks ("open at launch", MM:1940), and whether the diagnosis header is forwarded.
- An MCP reconnect that changes a description has no append-only form without `inline-tools`. Accepted as a logged break unless measurement says otherwise.
- User-code hooks: PreCompress (round 1 sends the hook's history, later rounds AppState's), BeforeModel, and a BeforeToolSelection hook that varies output can each break the prefix, inside a turn too. On a new account that is a 400 even in Phase 1, while the retry lands in PR 6. Moving the retry into PR 2 is the obvious hedge; owner to decide.
- Images: the downscale target size, and whether ingestion downscales for every provider (ingestion does not know which model will read the image).
- The exact `max_tokens` per model within 32-64K.

## 1. Components

- **Storage (decision 1):** `AnthropicStreamMapper` (block assembly), `LLMStreamEvent` (new case), `StreamAssembler` (carry blocks), `AnthropicClient.parseResponse` (non-stream), `Content.anthropicBlocks` in `Models.swift`, the strip in `LLMClient.encodeGeminiBody`, `iris.swift:2131`, the AfterModel drop.
- **Request shape (decisions 3-7, 13):** `AnthropicCapabilities` (new), `AnthropicClient` request building (`max_tokens`, `thinking`, `output_config`, betas, `block_binding`), the retry beside the TTL retry, `input_transformations` parsing, `ModelCallRecord` fields, `ConfigManager` effort settings, the streaming status line in `ChatView`.
- **Replay (decision 2):** the message builder in `AnthropicClient.swift:57-123`, selecting which assistant messages echo `anthropicBlocks`.
- **Append-only history (decisions 8-12, 15, 16):** `TurnContext`, the turn-context build at `iris.swift:1482-1539`, the cache-marker placement (`AnthropicClient.swift:147-174`), the role filter in the Gemini and OpenAI encoders, `assembledSystemPrompt` / `ensureSystemPrompt`, the tool assembly at `iris.swift:1541-1933`, `StickyTools`, `ToolExecutor.getTools`, `MCPManager`, `ConversationRotation`, `stripInlineDataFromHistory`, `AttachmentProcessor`.
- **Persistence:** new `Conversation` columns `frozenSystemPrompt`, `prefixMismatchBehavior` and the declared tool set; `Content.anthropicBlocks` and `systemClearAt` ride the existing history JSON. Every field uses `decodeIfPresent`, with an old-row decode test (invariant 1).
- **Docs (invariant 9):** AGENTS.md invariant 6, tool `description` fields and `oracleText` that describe gating, SYSTEM.md's description of the turn-context block, README sections on thinking, images and tools.

## 2. Verification

1. **Free, in `swift test`: `AppendOnlyRequestTests`.** Drive multi-turn scenarios through `FakeLLMClient` emitting fake thinking blocks: a fact turn, a rename trigger, an image turn, an MCP connect, a USER.md edit, and a restart and reload. Build each body with `AnthropicClient.makeURLRequest` (the `RequestDump` path). Assert that the system bytes and the non-deferred tool name set are unchanged, and that request N's messages are a prefix of N+1's, ignoring `cache_control`. Signatures are not checked, so fake blocks suffice.
   - Phase 1 adds: block order is preserved byte-for-byte; no gap in the middle; older turns carry no thinking.
   - Encoders: no `role: "system"` content reaches a Gemini or OpenAI body.
2. **Free, manual.** Convert `--dump-requests` output to one `.jsonl` per conversation and run `prefix_diff.py`. Read the `replayed thinking blocks` count first.
3. **Paid, owner approval at execution time.** `drop_block_probe.py --self-test --model claude-opus-5-5` (3 requests), then `--count-tokens --mode error`.
4. **Paid, owner approval at execution time.** The `caching` suite on the real lane (`perf/suites/caching.json`) plus a new tool-heavy multi-turn goal scenario. Three arms: today; Phase 1; Phase 2 with fixes and `drop_block` set. At least 5 repetitions, alternating arm order. Metrics: break share, first-break turn, distinct dropped blocks, cache read and write, output tokens, weighted cost per task. The turn-context cadence (decision 8) gets its own arm: every round against once per turn. #321's per-run temp-home path confounds any cross-run cache comparison, so compare within runs.

Phase 2 replay (PR 6) lands only after PRs 3-5 show zero mismatches in 1 and 2.

## 3. PR split

Each PR is based on main. None is stacked.

1. **Wire storage and request shape, no replay.** `anthropicBlocks` with the mapper, assembler and parser, and the Gemini strip; `AnthropicCapabilities`; `max_tokens`; beta header plumbing; `input_transformations` logging (record-only); `AppendOnlyRequestTests`; invariant 1 tests for old rows.
2. **Phase 1 replay.** Within-turn blocks only, older turns stripped deterministically. Tests: order preserved, no middle gaps.
3. **Append-only tools.** Deferred declarations, `tool_addition`, the persisted declared set, frozen descriptions. Amends invariant 6 and AGENTS.md, with the invariant 9 grep.
4. **Append-only system and context.** `clear_at` turn context, the frozen system prompt with deltas, the role-system filter in the other encoders, the rotation append.
5. **Images.** Keep on check models, downscale at ingestion.
6. **Phase 2 replay and binding retry.** Retry-on-400, the persisted behaviour, the perf record fields. Lands only after 3-5 show zero mismatches.
7. **Effort per tier and `display: "updates"`.** Independent; any time after PR 1.
8. **Paid measurement.** §2.3 and §2.4, with the owner's budget approval, results recorded in this spec.

## 4. Not in this deliverable

- `inline-tools-2026-09-15`: Claude API only, not on Vertex. Same-name tool changes stay a logged break.
- Per-message effort (`mid-conversation-output-config-2026-07-01`).
- Making user-code hooks (PreCompress, BeforeModel, BeforeToolSelection) prefix-safe. Their breaks show in `input_transformations`; only the AfterModel trailing drop is handled.
- A UI for reading thinking beyond the `"updates"` status line, and any user-facing pill for breaks.
- Replaying Vertex captures in the probe (not possible, PTM:53).
- Mid-conversation system messages on Sonnet 5, which does not support them.
- Changing the tier defaults to a model that runs the check.
