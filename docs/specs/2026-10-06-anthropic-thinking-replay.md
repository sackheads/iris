# Anthropic thinking replay and an append-only history

Status: **proposed** (2026-10-06). Implements #314. The design comes from the research brief of the same date (no API calls were made for it). The owner ruled on its open questions on 2026-10-06; those rulings bind this spec. Revised the same day after the `work` review on #384 (facts re-pinned, Phase 1 made deterministic, tools and turn context tightened, `max_tokens` split out).

Iris throws away every thinking block Anthropic returns. On Opus 5.5, Fable 5.1 and Sonnet 5.5, the signature carries the reasoning, so the model loses its own reasoning every time a tool result comes back. Replaying the blocks is only safe if the request prefix each signature was bound to is sent again byte-for-byte, and today Iris rebuilds that prefix in several places. This spec does it in two phases:

- **Phase 1** replays thinking within the current turn only, and stops replaying from any point in the turn where something edited the prefix.
- **Phase 2** replays every block, after the PRs that make the history append-only have landed.

## Facts this rests on

Doc paths are relative to the bundled claude-api skill's `shared/` directory: PTM = `preserved-thinking-migration.md`, CAUSES = `preserved-thinking-migration/causes.md`, MM = `model-migration.md`, PC = `prompt-caching.md`, PA = `platform-availability.md`, TUC = `tool-use-concepts.md`. Citations marked **(292)** are to skill version 2.1.292 as read by the `work` review on 2026-10-06; the rest are to 2.1.283, the newest copy on this machine, whose line numbers may have moved since. Where the docs and the issue differ, the docs win.

- **Which models check.** "Claude Fable 5.1, Claude Opus 5.5, and Claude Sonnet 5.5 today" (PTM:7 (292)). Mythos 5.1 "does not run this check" (MM:1605). Thinking is always on for Opus 5.5, which rejects `{"type": "disabled"}` and `{"type": "enabled", ...}` "at every effort level" (MM:1874); Fable 5.1 accepts only adaptive (MM:1322). Iris's tier defaults (`ConfigManager.swift:432-434`) include none of the three, so the check applies once a user picks `claude-opus-5-5`, `claude-fable-5-1` or `claude-sonnet-5-5`.
- **Who is enforced.** By default, accounts created on or after 2026-08-31 00:00 UTC (PTM:40, MM:1609). For Sonnet 5.5 this holds "on the Claude API and Amazon Bedrock (Google Cloud is not confirmed)" (MM:2144 (292)). Older accounts are enforced only when "a request ... sets `prefix_mismatch_behavior`".
- **What a signature binds.** "the top-level `system` prompt, the set of `tools`, and every message before the block" plus the producing model (PTM:7), "plus a chain to the previous thinking block" (MM:1609). Invalidators: editing, reordering or removing an earlier turn; "Injecting per-request text into an earlier turn ... that you remove or rebuild on the next request"; "Rebuilding the top-level `system` prompt or `tools` array"; different bytes behind an image URL (MM:1611-1617).
- **Which drops are allowed.** "The check accepts any **contiguous window** of the original thinking blocks: a run dropped from the front, a run dropped from the back, or both, and nothing else." And: "Once a block is removed, leave it out" (PTM §3).
- **What it does not bind.** `cache_control`, "reordering the `tools` array", and a model switch are Tier 0 (PTM:24). Tools are "compared as a name-keyed set", and a `defer_loading` tool counts only once something names it (PTM:88). Outside the prefix: `max_tokens`, `tool_choice`, `output_config` (effort included), and "the `thinking` configuration itself" (CAUSES:74). "Adding or removing a plain tool" is `tool_set_changed`; changing a description is `tool_schema_changed` (CAUSES:21).
- **The 400.** ``Invalid `signature` in `thinking` block. The block is bound to a different conversation.`` (MM:1624). "Retrying the same body fails the same way; the token-counting endpoint runs the same check" (MM:1621).
- **`drop_block`.** Header `anthropic-beta: thinking-binding-controls-2026-08-01`; body `"thinking": {"type": "adaptive", "block_binding": {"prefix_mismatch_behavior": "drop_block"}}` (MM:1632-1638). "`block_binding` works only with `thinking: {"type": "adaptive"}`"; Sonnet 5.5's `between_tools` rejects it (MM:2144 (292)). It "drops the first mismatched block **and every thinking block after it**", for that request only (MM:1641, 1649). The field without the header is a 400 ending in `block_binding: Extra inputs are not permitted`. "The header without the field does **not** turn enforcement on"; mismatched blocks reach the model, listed as `thinking_mismatch_allowed` (PTM:134). "copying the field into production lifts the exemption on every request that carries it" (PTM:182). Documented recovery: "retry once with the beta header and `prefix_mismatch_behavior: "drop_block"`, and store that choice with the session so every later request sends it too, including after a restart" (CAUSES:93). Yet "`drop_block` ... is not a fix" (PTM:36).
- **`input_transformations`.** A top-level array beside `usage`, `[]` when nothing happened, present on every response when the header is sent. Entries: `{"type": "thinking_dropped", "path": ..., "reason": "prefix_binding_mismatch"}`, reason `model_binding_mismatch`, and `thinking_mismatch_allowed`. Streaming, it arrives in `message_start`, and again in the final `message_delta` only after a mid-stream server-side model fallback. Ignore unknown types and reasons (PTM:145). Count a break once per conversation, keyed by `signature` (PTM:168). The `anthropic-thinking-prefix-mismatch` header: "Use it if present; never depend on it" (PTM:146).
- **System messages, `clear_at`, tool changes.** Mid-conversation system messages run on the PC:67 list plus Claude Sonnet 5.5, "not Claude Sonnet 5" (PA:44 (292)); tool changes (`mid-conversation-tool-changes-2026-07-01`) and `clear_at` (`mid-conversation-system-clear-at-2026-08-21`) on the same models (PA:45-46 (292)). `{"role": "system", "clear_at": "next_user_message", "content": "..."}`; "a cleared message costs no input tokens" (MM:1705, 1719). Text-only, "takes no `cache_control`", and "one followed directly by another `user` message is a 400"; "a `tool_result`-only user message counts as the next user message" (MM:1724). It "cannot be `messages[0]`" (PC:81). On Opus 5.5 `clear_at` is "a limited beta"; "without it, append the reminder as a text block after the `tool_result` blocks and leave earlier copies in place" (MM:1946 (292)).
- **Tool changes.** "A tool you plan to add must already be declared in `tools[]` with `"defer_loading": True`" (TUC:301); announce it with `tool_addition`, "never append a regular tool"; withdraw with `tool_removal` and leave the entry (PTM:197), placed "immediately before an assistant message, or last in messages" (TUC:290). A same-name change has no append-only form except `inline-tools-2026-09-15`, "Claude API only" (CAUSES:59). A deferred, unreferenced tool is "not loaded into the model's context" (TUC:301).
- **Effort and display.** Opus 5.5's default effort is `medium` (MM:2007); Fable 5.1's is `high` (MM:1758). `output_config: {"effort": ...}`; sending the default "is equivalent to omitting it" (PC:240); changing it invalidates the prompt cache (MM:2010) but not thinking (CAUSES:74). `display` defaults to `"omitted"` (blocks return `thinking: ""`; MM:1348). `"updates"` needs `thinking-display-updates-2026-08-18` (PA:48). On Opus 5.5 "text between tool calls comes back in thinking blocks" (MM:1985). Replay blocks "exactly as received - including blocks whose `thinking` text is empty" (MM:1350).
- **Cost.** On the PC:240 models "previous-turn thinking blocks are preserved by default", so replay keeps the cache valid. Replayed blocks are "counted in input tokens" (CAUSES:13); dropped blocks are "not billed" (PTM:145), but "A dropped block changes the cached prefix from its position onward" (MM:1599). Cache reads are 0.05x on Opus 5.5 and 0.025x on Fable 5.1 (MM:2023, 1678).
- **Model switches.** "the API drops what the target can't read, unbilled" (MM:1601). Opus 5.5 blocks are read by Fable 5.1 and Mythos 5.1 on the Claude API (MM:1940); Fable 5.1 blocks only by Mythos 5.1 (MM:1597).
- **Vertex.** The same beta names go in the `anthropic-beta` header (MM:1609, PA:49). `inline-tools` is not offered. The probe "cannot replay captures taken on ... Vertex AI" (PTM:53).
- **In Iris, within one turn the prefix is mostly append-only.** System and tools are set once per turn (`iris.swift:1958`), even when `update_soul` or skill CRUD runs mid-turn; steers land at round boundaries; retries and fallback are Tier 0. The exceptions are a mid-turn edit of the entry or history by the UI (`requestContents` reports `firstDrop`, `iris.swift:1947-1956`), a modifying PreCompress hook (round 1 sends its list, later rounds AppState's, `:1936-1950`), BeforeModel rewrites (per round), and AfterModel rewrites of the stored reply. BeforeToolSelection fires once per turn, before the round loop (`:1926`), so it only breaks across turns.

## 0. Decided

Each decision names its default, why, and the cost if wrong. **[P1]** lands in Phase 1, **[P2]** in Phase 2, **[any]** is independent of the phases.

1. **Store the assistant content array as received. [P1]** `Content.anthropicBlocks: String?` holds the JSON array of the reply's blocks, assembled by `AnthropicStreamMapper` per block index (text, `thinking_delta`, `signature_delta`, `partial_json` bytes kept verbatim and never re-serialised, `redacted_thinking.data`), carried through a new `LLMStreamEvent` case and `StreamAssembler` so the non-stream path keeps it, and set on the `Content` at `iris.swift:2131`. `AnthropicClient` echoes `anthropicBlocks` when present and builds from `parts` otherwise. `parts` stays for the UI, hooks and other providers.
   - An incomplete block (a stream that died mid-thinking) is never stored; only `partial` text is, as today.
   - Invariant 1: `Content.init(from:)` is custom (`Models.swift:234-238`), so the field gets `decodeIfPresent` and a `CodingKeys` case. History rows are whole-`Content` JSON, so no column. `LLMClient.encodeGeminiBody` must strip the field. `read_conversation` and search ignore signatures.
   - *Why:* `StreamAssembler.response()` merges every text block into one part and appends the calls after it, so order and boundaries are lost, and progress blocks sit between `text` and `tool_use` on Opus 5.5 (MM:1985). *Cost if wrong:* history rows grow by the signature bytes.
2. **Replay rules.**
   - **Phase 1 [P1]:** replay only blocks from the current turn, and only those produced after the turn's most recent prefix-editing event, so every drop is a front run (PTM §3). Older turns go out without thinking, deterministically. The events, each counted as falling just before the request it changes:
     - an AfterModel rewrite of round k's reply: stop replaying the turn's blocks up to and including round k (dropping round k alone would leave a gap once round k+1 adds a block);
     - a mid-turn UI edit or deletion of the entry or history (5a's `firstDrop`);
     - a PreCompress hook that modified the history (the event falls at round 2, when AppState's list replaces the hook's);
     - a BeforeModel rewrite, including one that returns JSON without `anthropicBlocks`. A hook that rewrites every round therefore means no replay for that turn.
   - The `drop_block` retry (decision 6) ships in Phase 1 as the backstop for causes nobody predicted, not as the plan. Phase 1 sends no `block_binding` field until that retry fires, so enforcement is unchanged; its 400 risk is confined to edits the event list misses.
   - **Phase 2 [P2]:** replay every block, once PRs 3-5 land. Phase 2 never resends a block Phase 1 stripped: at a conversation's first Phase 2 send, persist `Conversation.replayFromTurn` (`decodeIfPresent` plus a column), and never replay blocks from turns before it. Otherwise PR 6's first request on every existing conversation of a new account is a 400 followed by a permanent `drop_block`.
   - **Both:** never edit, reorder or thin the middle; send blocks on a model switch and let the API drop what it must; once a strip is recorded, keep it stripped.
   - *Why (ruling 1):* Phase 1 fixes the headline (reasoning lost when the tool result returns) without the append-only work. Phase 2 matters for goal loops, where each reprompt is a new turn. *Cost if wrong:* Phase 1 alone loses cross-turn reasoning and its cache reads.
3. **One `AnthropicCapabilities` table that grows with its readers. [P1, grows]** Keyed on the model id after `vertexModelID` normalization. PR 1 ships only `runsPrefixCheck` (Opus 5.5, Fable 5.1, Sonnet 5.5). `supportsSystemMessages` and `supportsToolChanges` (PA:44-45) arrive with PRs 3-4, effort and display with PR 7. Each field lands with its first reader. *Cost if wrong:* a model added to the docs later runs the unknown-id paths until the table learns it.
4. **Beta headers, only to models known to take them. [P1, grows]** Iris sends no `anthropic-beta` today (`AnthropicClient.swift:255-262`). Phase 1 sends `thinking-binding-controls-2026-08-01` only to known `runsPrefixCheck` models, never to unknown ids: a beta a model rejects is a 400 on every request. For an unknown id that returns the binding 400, the retry adds the header and field on the fly. Later: `mid-conversation-system-clear-at-2026-08-21` and `mid-conversation-tool-changes-2026-07-01` (P2), `thinking-display-updates-2026-08-18` (decision 11). Never `inline-tools-2026-09-15`. `block_binding` is sent only with `thinking: {"type": "adaptive"}`, never with `between_tools`.
5. **Vertex and direct. [any]** The same betas in the same header on both. On Vertex, `input_transformations` is the only signal and the probe cannot run, so the self-test there is Iris's own client reading it. A custom `baseURL` proxy may strip the header or the field, so the self-test runs through that path too.
6. **Binding policy (ruling 2). [P1]** On known `runsPrefixCheck` models, always send the header and leave `prefix_mismatch_behavior` unset. On a 400 containing "bound to a different conversation", retry once with `drop_block` before any stream event is yielded (the TTL-retry shape at `AnthropicClient.swift:288-306`), and persist `prefixMismatchBehavior = "drop_block"` on the conversation (`decodeIfPresent` plus a column) so every later request sends it, across restarts (CAUSES:93). `"error"` is used only in CI, on fake-lane replays. The field is only ever set after a binding 400, which an unenforced account never receives, so no exemption is lifted (PTM:182). *Cost if wrong:* the persisted `drop_block` outlives the turn that broke, which is heavy for a one-turn break; that is why decision 2 stops the known causes first.
7. **Log `input_transformations`. [P1 raw, P2 counted]** Phase 1 parses it from `message_start`, the final `message_delta` and the non-stream top level, ignores unknown types and reasons, stores the raw entries on `ModelCallRecord` (`decodeIfPresent`; perf JSON is persisted), and prints a console line, plus the diagnosis header if present. Phase 2 adds per-conversation break counting keyed by `signature` (PTM:168), for the measurement in §2.4. No user pill. *Cost if wrong:* log noise.
8. **Turn context moves to `clear_at` (ruling 5). [P2]** On models with system messages (PA:44), 5a's block is no longer inserted into the turn's entry.
   - The live copy carries only the volatile parts (time, budget, goal and checkpoint state, the briefing). The stable parts (AGENTS.md, USER.md, skills, rules) travel as decision 9's system deltas.
   - `{"role":"system","clear_at":"next_user_message","content":<volatile>}` is appended after the entry and after each `tool_result` message, **every round**. Once per turn is not an option: the first `tool_result` clears the copy, so later rounds would run without context. Each copy is persisted with the assistant reply that follows it, as `Content(role: "system")` with `systemClearAt` (`decodeIfPresent`). A copy whose round failed is never persisted, because a later steer would follow it directly (the 400 at MM:1724).
   - *Fallback* for unknown ids and for accounts without the `clear_at` beta: the documented form, a text block appended after the `tool_result` blocks with earlier copies left in place (MM:1946 (292)). Not 5a, whose insert-and-strip is `reminder_stripped` (CAUSES:45) every turn. Models that run no check (Sonnet 5, Haiku 4.5) keep 5a as is.
   - *Marker effects:* `TurnRequest`'s anchors and byte check go unused on this path. Marker (b), the end of turn k-2, stops being the read point; with nothing removed, turn k-1's rounds become readable. Markers skip `role: "system"` messages (no `cache_control`) and land on the preceding user turn.
   - *Other encoders:* the Gemini and OpenAI encoders must filter `role == "system"`. Today both map any non-`model` role to `user` (`AnthropicClient.swift:68`, `OpenAIClient.swift:23`).
   - *Cost if wrong:* the live copy is uncached input every round, 20-40x 5a's cached read on that slice; keeping it to the volatile parts keeps that small.
9. **Freeze the system prompt per conversation (ruling 3). [P2]** On check models with system messages (Opus 5.5, Fable 5.1, Sonnet 5.5), freeze the rendered system text at first send, or for an existing conversation at its first Phase 2 send (the `replayFromTurn` point), as `Conversation.frozenSystemPrompt` (`decodeIfPresent` plus a column, as `upsertMetadata` at `ConversationStore.swift:745-760` needs). Send those bytes for the rest of the conversation. A change to SOUL, USER.md, AGENTS.md, skills or rules appends one `role: "system"` delta naming what changed, with the new section text. Declared, logged boundaries: a new conversation, rotation, and an app upgrade that changes SYSTEM.md. *Why:* the prompt is re-rendered by the model's own tools, by commands, and by any USER.md or AGENTS.md mtime change, through one engine-wide cache, so an edit in one conversation re-renders every conversation's prefix. *Cost if wrong:* one logged break per upgrade.
10. **Tools on check models: a persisted declared array, `defer_loading` and `tool_addition`; invariant 6 amended. [P2]** On `supportsToolChanges` models, the conversation's first request declares every tool it could ever see: state-gated tools, workflow triggers, and the MCP tools known then. Plain where today's gate is open, `defer_loading: true` otherwise. When a gate first opens or a trigger turn arrives, append a `role: "system"` `tool_addition` and leave the tool added (or withdraw it with `tool_removal`, placed as TUC:290 requires). Late MCP or Google tools are appended with `defer_loading` and a `tool_addition`. Descriptions rendered from state (`maxRunsPerHourForWatch`, `searchMemoryDescription(isPinned:)`) are frozen per conversation.
    - **Persistence:** only check models persist the declared array, with its `defer_loading` flags and descriptions, on `Conversation` (`decodeIfPresent` plus a column). On load it is intersected with the tools this build still has, so a tool an upgrade renamed or removed is never declared (a logged break). 5c's off-state refusal at dispatch (5c §0.2) carries more weight once the set survives restarts. Other providers keep 5c §0.1 as decided: the sticky set is not persisted.
    - *Invariant 6 amendment:* "On models that support mid-conversation tool changes, gated tools are declared at the conversation's first request with `defer_loading: true` and announced with `tool_addition` when their gate opens. A deferred, unreferenced tool is not loaded into context (TUC:301), so it costs no prompt tokens." Invariant 9 applies: grep the tool descriptions and `oracleText` that describe gating.
    - *Why:* each first declaration of a plain sticky tool is `tool_set_changed`; a restart shrinks the in-memory sticky set, which on a new account is a break on every conversation after every relaunch; triggers are declared and removed within a turn. *Cost if wrong:* a larger first request; unprompted eagerness on a deferred tool, which §2 checks.
11. **Effort per tier and `display: "updates"`. [any]** Add `anthropicEffort{Easy,Medium,Hard}` to `ConfigManager`, default "model default" (omitted; PC:240). Send `output_config.effort` only to models with effort, never to `claude-haiku-4-5`. Send a `thinking` object only to adaptive models. On models the table marks for display updates, send `display: "updates"` with its beta and stream `thinking_delta` text into the streaming row as a status line, not persisted to `messages` (it is in `anthropicBlocks`). *Why:* it brings back the between-tool narration Opus 5.5 moved into thinking. *Cost if wrong:* an effort change invalidates the prompt cache (MM:2010).
12. **Images (ruling 4). [P2]** On check models, images are kept in history, not stripped, and downscaled at ingestion (`AttachmentProcessor.swift` has none today), the only option that "loses nothing" (PTM:203). Elsewhere `stripInlineDataFromHistory` stays. *Why:* stripping is `media_stripped` and costs every later turn's reasoning on each image turn. *Cost if wrong:* images re-read from cache on every later turn.
13. **Tier switches. [P2]** Only a Settings change switches tiers; the main engine is fixed at `.medium` (`AppState.swift:716`). Send the same history. Before the request, strip only what the target rejects: persisted `role: "system"` and `tool_addition` messages for models without system messages. Those models run no check, so this is safe, and the stored history is untouched for the return trip. `model_binding_mismatch` drops are reported separately.
14. **Rotation and subagents. [P2]** Rotation is simple compaction (MM:1665), but `ConversationRotation.swift:150-163` prepends the summary at index 0; when the history holds a replayable block it appends instead. Subagent and evaluator engines run the same `processInputBody` over their own conversations, so they inherit decisions 1-12 and persist and replay their own system and `tool_addition` messages (CAUSES:46).

**Open.**
- Vertex (probe pending): whether enforcement applies on Google Cloud at all ("not confirmed"), whether Fable 5.1 keeps Opus 5.5's blocks there ("open at launch", MM:1940), and whether the diagnosis header is forwarded.
- How Iris learns that an account lacks the `clear_at` limited beta, so decision 8 can take the fallback. The self-test should detect it.
- Unknown ids have no system messages, so decision 9's delta has no form there. This spec does not freeze the prompt on them; a re-render is a logged break.
- An MCP reconnect that changes a description has no append-only form without `inline-tools`. Accepted as a logged break unless measurement says otherwise.
- Images: the downscale target size, and whether ingestion downscales for every provider (it does not know which model will read the image).

## 1. Components

- **Storage (decision 1):** `AnthropicStreamMapper`, `LLMStreamEvent` (new case), `StreamAssembler`, `AnthropicClient.parseResponse`, `Content.anthropicBlocks` in `Models.swift`, the strip in `LLMClient.encodeGeminiBody`, `iris.swift:2131`.
- **Phase 1 replay (decision 2):** the message builder in `AnthropicClient.swift:57-123`; a per-turn replay floor in `processInputBody`, raised by the AfterModel, `firstDrop`, PreCompress and BeforeModel paths.
- **Request shape (decisions 3-7, 11):** `AnthropicCapabilities` (new), betas, `block_binding`, the retry beside the TTL retry, `input_transformations` parsing, `ModelCallRecord` fields, `ConfigManager` effort settings, the streaming status line in `ChatView`.
- **Append-only history (decisions 8-10, 12-14):** `TurnContext` and the build at `iris.swift:1482-1539`, cache-marker placement (`AnthropicClient.swift:147-174`), the role filter in the Gemini and OpenAI encoders, `assembledSystemPrompt` / `ensureSystemPrompt`, the tool assembly at `iris.swift:1541-1933`, `StickyTools`, `ToolExecutor.getTools`, `MCPManager`, `ConversationRotation`, `stripInlineDataFromHistory`, `AttachmentProcessor`.
- **Persistence:** `Conversation` columns `prefixMismatchBehavior` (P1), `replayFromTurn`, `frozenSystemPrompt` and the declared tool array (P2); `Content.anthropicBlocks` and `systemClearAt` ride the history JSON. Every field uses `decodeIfPresent`, with an old-row decode test (invariant 1).
- **Docs (invariant 9):** AGENTS.md invariant 6, tool `description` fields and `oracleText` that describe gating, SYSTEM.md's description of the turn-context block, README sections on thinking, images and tools.

## 2. Verification

1. **Free, in `swift test`: `AppendOnlyRequestTests`.** Scenarios run through `FakeLLMClient` emitting fake thinking blocks; each body is built with `AnthropicClient.makeURLRequest` (the `RequestDump` path). Signatures are not checked, so fake blocks suffice.
   - **PRs 1-2, within-turn only:** request N's messages are a prefix of N+1's within a turn, ignoring `cache_control`; block order is preserved byte-for-byte; no gap in the middle; older turns carry no thinking. One case per decision 2 event (AfterModel rewrite, `firstDrop`, modifying PreCompress, BeforeModel rewrite, BeforeModel JSON without `anthropicBlocks`), each asserting that the replayed blocks form a front-dropped window. No beta header reaches an unknown id.
   - **PRs 3-5, cross-turn, each added by the PR that makes it true:** system bytes unchanged across turns, the non-deferred tool name set only grows, and request N is a prefix of N+1 across turns, through a fact turn, a rename trigger, an image turn, an MCP connect, a USER.md edit, and a restart and reload.
   - Encoders: no `role: "system"` content reaches a Gemini or OpenAI body.
   - PR 6: a conversation with Phase 1 history replays nothing before `replayFromTurn`.
2. **Free, manual.** Convert `--dump-requests` output to one `.jsonl` per conversation and run `prefix_diff.py`. Read the `replayed thinking blocks` count first.
3. **Paid, owner approval at execution time.** `drop_block_probe.py --self-test --model claude-opus-5-5` (3 requests), then `--count-tokens --mode error`.
4. **Paid, owner approval at execution time.** The `caching` suite on the real lane (`perf/suites/caching.json`) plus a new tool-heavy multi-turn goal scenario. Three arms: today; Phase 1; Phase 2 with fixes and `drop_block` set. At least 5 repetitions, alternating arm order. Metrics: break share, first-break turn, distinct dropped blocks (signature-keyed, decision 7), cache read and write, output tokens, weighted cost per task. #321's per-run temp-home path confounds any cross-run cache comparison, so compare within runs.

Phase 2 replay (PR 6) lands only after PRs 3-5 show zero mismatches in 1 and 2.

## 3. PR split

Each PR is based on main. None is stacked.

1. **Wire storage, no replay.** `anthropicBlocks` with the mapper, assembler and parser, and the Gemini strip; `AnthropicCapabilities` with `runsPrefixCheck` only; the binding header to known check models; raw `input_transformations` on `ModelCallRecord` plus a console line; within-turn `AppendOnlyRequestTests`; invariant 1 tests for old rows.
2. **Phase 1 replay.** Within-turn blocks after the last prefix-editing event; the `drop_block` retry and persisted `prefixMismatchBehavior` as the backstop. Tests: the decision 2 event cases.
3. **Append-only tools.** `supportsToolChanges`; deferred declarations, `tool_addition`, the persisted declared array on check models with the load-time intersection, frozen descriptions. Amends invariant 6, with the invariant 9 grep.
4. **Append-only system and context.** `supportsSystemMessages`; `clear_at` turn context with the volatile split and the text-block fallback; the frozen system prompt with deltas; the role filter in the other encoders; the rotation append.
5. **Images.** Keep on check models, downscale at ingestion.
6. **Phase 2 replay.** `replayFromTurn`, signature-keyed break counting. Lands only after 3-5 show zero mismatches.
7. **Effort per tier and `display: "updates"`.** Independent; any time after PR 1.
8. **Paid measurement.** §2.3 and §2.4, with the owner's budget approval, results recorded in this spec.

## 4. Not in this deliverable

- `max_tokens`. The hardcoded 4096 (`AnthropicClient.swift:177`) must cover thinking plus the reply on these models today, replay or not ("64K has worked well", MM:1884). It ships separately as a bug fix.
- `inline-tools-2026-09-15`: Claude API only, not on Vertex. Same-name tool changes stay a logged break.
- Per-message effort (`mid-conversation-output-config-2026-07-01`).
- Making user-code hooks prefix-safe across turns (PreCompress, BeforeModel, BeforeToolSelection). Within a turn, decision 2 contains them; across turns their breaks show in `input_transformations`.
- A UI for reading thinking beyond the `"updates"` status line, and any user-facing pill for breaks.
- Replaying Vertex captures in the probe (not possible, PTM:53).
- Mid-conversation system messages on Sonnet 5, which does not support them.
- Changing the tier defaults to a model that runs the check.
