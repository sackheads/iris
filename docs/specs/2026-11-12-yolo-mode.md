# Spec: YOLO Mode (#1099)

## Problem
While Vibecop tuning and agent profiles are still maturing, interactive coding sessions require too many manual approval clicks for routine operations (`run_command`, file writes, `search_web` after reading files, memory/skill updates, etc.). We need a fast, per-session runtime toggle (`/yolo`) that approves all tool calls in that session and its delegated subagents/evaluators without prompting, while keeping unattended background runs (`isBackground`) and external MCP guest sessions (`isGuest`) strictly under their existing fail-closed boundaries.

## User Interface & Slash Command

### `/yolo` Command
Typed into the composer in any user-facing conversation:
- `/yolo` — prints current status: `Yolo mode is on.` or `Yolo mode is off.`
- `/yolo on` — enables YOLO mode for the active conversation, resolves any currently pending approval prompts for this conversation (and its delegates) as approved, plays the Vengabus synth jingle, and emits `Yolo mode is on.`
- `/yolo off` — disables YOLO mode for the active conversation, plays the power-down synth sound, and emits `Yolo mode is off.`
- Any other argument emits usage: `Usage: /yolo [on|off]`

Autocomplete entry in `SlashCommandItem.allCommands`:
- `id: "yolo"`, `command: "/yolo"`, `usage: "/yolo [on|off]"`, `description: "Show or toggle YOLO mode (auto-approve all tools in this session)"`

### Audio (`YoloSynth`)
`YoloSynth` (`Sources/IrisKit/YoloSynth.swift`) synthesizes two PCM buffers via `AVAudioEngine` + `AVAudioPlayerNode` at 44.1 kHz mono:
- `playVengabusYolo()`: 90s Eurodance horn hook (sawtooth + square blend with per-note attack/release envelope and global fade-out) played when `/yolo on` transitions YOLO mode from off to on (or every time `/yolo on` is invoked).
- `playPowerDown()`: 1.6-second exponential pitch drop (523.25 Hz C5 down to 36 Hz sub-bass with closing low-pass filter) played when `/yolo off` is invoked.
- `AppState` holds an `@ObservationIgnored var yoloAudio: YoloAudioPlaying` seam (defaulting to a lazy `YoloSynth` when not running under unit tests, and a no-op under `XCTestCase` / Swift Testing so tests never spin up `AVAudioEngine` or play audio during test runs). `YoloSynth` buffer generation is also exposed as pure `makeVengabusBuffer()` / `makePowerDownBuffer()` methods so tests can verify sample synthesis deterministically without hardware output.

## Scope & Security Boundaries

1. **Per-Session, Inherited by Delegates (`isYoloMode(_ conversationId: UUID?) -> Bool`):**
   - Stored on `AppState` per conversation (`yoloConversations: Set<UUID>`), transient in-memory (resets on app quit/relaunch; `/new` starts with YOLO off).
   - Walked through `delegationRoot(of: conversationId)`, so subagents and goal evaluators spawned by a YOLO-enabled conversation inherit YOLO mode automatically.
2. **Hard Carve-outs (Never YOLO):**
   - **MCP Guests (`conversation.isGuest == true`):** Refused before YOLO is consulted (`requestApprovalSource` returns `nil`).
   - **Unattended Background Runs (`conversation.isBackground == true`):** Checked before YOLO in `requestApprovalSource`, `outboundGate`, and `holdContextWriteIfTainted`. A background job run (and any subagent it delegates to, which inherits `isBackground = true`) never gets YOLO mode.
3. **What YOLO Mode Approves in an Attended Session:**
   - **`requestApprovalSource`:** Immediately after the `isGuest` and `isBackground` checks (and `autoApproveTools`), if `isYoloMode(conversationId)` is true, returns `.yolo` without consulting `humanOnly`, `irisWrite`, the allowlist, or Vibecop. Commands run unrestricted on the host (or in the sandbox if the session is sandboxed).
   - **`outboundGate` (#812):** If ` !isUnattended` and `localState.isYoloMode(conversationId)` is true, returns `.approved(ToolApproval(layer: .yolo))` without prompting.
   - **`holdContextWriteIfTainted` (#813):** If `!isBackground` and `localState.isYoloMode(conversationId)` is true, returns `nil` (does not hold `save_fact`, `manage_fact`, `create_skill`, `update_skill`, `delete_skill`, `update_memory`, `update_user_profile`, `update_soul`, or `write_file` to standing context files; executes them immediately).
   - **`gateScriptReview` (#187 §7 / #330):** When `state.isYoloMode(conversationId)` is true (and not a background conversation), `gateScriptReview` auto-approves without running Vibecop or enqueuing a modal prompt.
   - **Pending Approvals Flush:** Turning `/yolo on` immediately approves any `pendingApprovals` already queued for that conversation or its delegates (`delegationRoot(of: req.conversationId) == convId`), so turning `/yolo on` while an approval banner is sitting on screen clears it immediately.
4. **Transcript Audit Trail (`ToolApproval.Layer.yolo`):**
   - `AppState.ApprovalSource.yolo` maps to `ToolApproval.Layer.yolo`.
   - `ToolApproval.layerLine` renders `"Approved (YOLO mode)."` on the tool pill and in markdown/plain-text exports.
   - Only the `/yolo` slash command handler in `AppState` can enable or disable YOLO mode; no tool, hook, or model output can invoke it.

## Verification Plan
1. Unit tests in `Tests/irisTests/YoloModeTests.swift` covering:
   - `/yolo`, `/yolo on`, `/yolo off`, invalid args, and `SlashCommandItem` matching.
   - `requestApprovalSource` returning `.yolo` for `run_command`, `write_file`, `.iris/` writes (`irisWrite`), and `humanOnly` calls in a YOLO session without calling Vibecop or queueing a user prompt.
   - Subagent/delegate inheritance via `delegationRoot(of:)`.
   - Background (`isBackground`) and guest (`isGuest`) conversations refusing YOLO mode even if their IDs were somehow inserted.
   - `outboundGate` auto-approving tainted outbound calls (`search_web`, `gmail_send_email`) with `.yolo` in a YOLO session while still refusing unattended runs.
   - `holdContextWriteIfTainted` bypassing context holds in a tainted YOLO session while still holding in non-YOLO or background sessions.
   - `gateScriptReview` auto-approving in a YOLO session.
   - Turning `/yolo on` resolving already-queued `pendingApprovals` for that session and its delegates.
   - `YoloSynth` PCM buffer synthesis (`makeVengabusBuffer`, `makePowerDownBuffer`) producing non-empty, finite audio frames within expected amplitude bounds, and audio hook invocation on `/yolo on` and `/yolo off`.
