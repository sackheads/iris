# Inbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A durable, threaded Inbox where pending human-decision items from any agent collect in one readable place and are answered in place, with the answer routed back to the right agents.

**Architecture:** A new durable sub-store (`InboxStore`) on the `ConversationStore` writer, in the `PeerLedger` mould, holding items and their thread entries independently of any conversation (so a reply outlives a dead emitter). A gated agent tool emits items through the `publishToTopic` skeleton (guard-judge once → rate-limit → persist), but items wait for Brian rather than fanning out. Submitting an answer resolves the route-back targets at answer time and delivers through the existing `deliverPeerMessage` path, persisting "awaiting delivery" when no recipient is live. A mailbox view hangs off a new sidebar row under the pinned Iris conversation.

**Tech Stack:** Swift, SwiftUI (`@Observable` AppState), GRDB (SQLite via `DatabaseWriter`), Swift Testing. Local-first macOS app.

**Spec:** `docs/specs/2026-11-07-inbox-design.md` (read it alongside this plan).

## Global Constraints

- **Invariant 1 (persistence):** every field on a persisted `Codable` uses `decodeIfPresent(...) ?? default`; every DB-row decode is defensive and skips an unreadable row rather than trapping (copy `PeerLedger.decode`, PeerLedger.swift:197). A forgotten one makes the whole table unreadable.
- **Invariant 6 (tool gating):** the emit tool is declared only on attended `principal == .main` turns and once-sticky; declaration alone is not enough — the dispatcher refuses an un-offered call (#811, iris.swift:4923) and the handler re-guards `principal == .main && !isUnattended`.
- **Deadlines:** use `UptimeClock` (UptimeClock.swift) / dispatch, never `Date()` — a sleep must not count. Persist the absolute deadline as a `Date` for display and launch catch-up, but gate the live countdown on `UptimeClock`.
- **Guard:** an emit is guard-judged once at emit, tier-3, context tag `"inbox_emit"`, charged to the emitter, fail-closed with a rate-token refund (reuse `publishToTopic`'s shape, iris.swift:1061).
- **Tests never mutate process-global state:** no `ConfigManager.shared`; inject the store (`ConversationStore`/`InboxStore`) and a `PeerRateLimiter(now:)` with an injected clock; scope the guard tiers.
- **Reading the Inbox must not load or re-evaluate the pinned Iris conversation** (the second-brain-must-not-be-taxed separation).
- macOS floor is not a constraint; a current-OS API is fine.

## Review Focus

Inputs the spec implies but a task's happy-path tests won't exercise, most likely to bite, each pinned to the owning task:

- **A reply to a now-dead/archived emitter, answered hours later** must persist and redeliver, never drop (`SessionAddressError.inactive`, SessionDirectory.swift:195). → Task 3.
- **A foreign agent appends/reopens another chain's `thread_id`** must be refused, not silently merged (thread ownership / anti-goal #3). → Task 1.
- **A guard-blocked emit** must fail closed, refund the rate token, and store nothing. → Task 2.
- **A timed-veto deadline that passes while the Mac is asleep or Iris isn't running** must fire once on next launch (or hold, if tainted), from the absolute deadline, idempotently. → Task 4.
- **A malformed/older inbox row on decode** must be skipped, never trap the whole load. → Task 1.

**Interfaces — Produces:**
- `enum InboxResponseMode: String, Codable, Sendable { case optionsAndFreeform, freeform, timedVeto, notification }`
- `enum InboxItemState: String, Codable, Sendable { case open, answered, awaitingDelivery, closed, stale }`
- `struct InboxOption: Codable, Equatable, Sendable { let id: String; var label: String; var pros: [String]; var cons: [String] }`
- `struct InboxAnswer: Codable, Equatable, Sendable { var chosenOptionId: String?; var freeText: String?; var at: Date }`
- `struct InboxItem: Codable, Equatable, Sendable` with: `let id: String`, `let threadId: String`, `let ownerChain: String` (the emitter identity that owns the thread), `let emitter: UUID`, `let emitterLabel: String`, `var title: String`, `var situation: String`, `var options: [InboxOption]`, `var responseMode: InboxResponseMode`, `var routeBack: [String]`, `var notify: [String]`, `var deadline: Date?`, `var vetoDefaultOptionId: String?`, `var emitterTainted: Bool`, `var state: InboxItemState`, `let createdAt: Date`, `var lastActivityAt: Date`, `var answer: InboxAnswer?` — with a custom `init(from:)` using `decodeIfPresent ?? default` on every field.
- `struct InboxThreadEntry: Equatable, Sendable { let seq: Int64; let itemId: String; let kind: String /* "question"|"answer"|"followup" */; let author: String; let body: String; let at: Date }`
- `final class InboxStore: Sendable` holding `private let writer: any DatabaseWriter`, `init(writer:)`, and:
  - `func newItemId() throws -> String` / `func newThreadId(ownerChain:) throws -> String` (random hex, re-rolled on collision, mirroring PeerLedger.swift:29; thread id namespaced by owner)
  - `@discardableResult func createItem(_ item: InboxItem, question: String) throws -> InboxItem` (inserts the item + a `"question"` thread entry in one write)
  - `func appendFollowup(threadId: String, fromChain ownerChain: String, author: String, body: String, at: Date) throws -> Result<Void, InboxError>` — **refuses with `.notOwner` when `ownerChain` != the thread's stored owner**, else appends a `"followup"` entry and flips the item to `.open`
  - `func recordAnswer(itemId: String, answer: InboxAnswer) throws` (writes answer + `"answer"` entry, sets `.answered`)
  - `func setState(itemId: String, _ state: InboxItemState) throws`
  - `func item(id: String) throws -> InboxItem?`, `func thread(itemId: String) throws -> [InboxThreadEntry]`, `func openItems() throws -> [InboxItem]`
  - `static func decode(_ row: Row) -> InboxItem?` (defensive, skips unreadable rows)
- `enum InboxError: Error, Equatable { case notOwner, unknownThread }`

Schema (`v35_inbox`): table `inbox_items` (`id` TEXT PK, `threadId`, `ownerChain`, `emitter`, `emitterLabel`, `title`, `situation`, `optionsJSON`, `responseMode`, `routeBackJSON`, `notifyJSON`, `deadline` nullable, `vetoDefaultOptionId` nullable, `emitterTainted` INT, `state`, `createdAt`, `lastActivityAt`, `answerJSON` nullable) and table `inbox_thread` (`seq` autoinc PK, `itemId`, `kind`, `author`, `body`, `at`) with an index on `(itemId, seq)` — both `ifNotExists: true`, standalone (no FK to `conversations`, per the `pending_context_writes` precedent, ConversationStore.swift:716).

## Task 3: Answer routing and durable delivery

**Files:**
- Modify: `Sources/IrisKit/iris.swift` — add `func submitInboxAnswer(itemId:choice:freeText:) async -> InboxSubmitOutcome` and `func redeliverAwaitingInbox() async`; reuse `deliverPeerMessage` (886) and `SessionDirectory.resolve` (177)
- Modify: `Sources/IrisKit/AppState.swift` — mark/clear an inbox unread/badge signal beside `unreadReplies` (528)
- Test: `Tests/irisTests/InboxRoutingTests.swift`

**Interfaces — Consumes:** Task 1 store, `deliverPeerMessage`, `SessionDirectory.resolve`, `SessionRoles.holder`. **Produces:** `enum InboxSubmitOutcome { case delivered(Int), awaitingDelivery, mixed(delivered: Int, awaiting: Int) }` and `redeliverAwaitingInbox()`.

Behaviour: on submit, `recordAnswer` on the thread; for each `route_back` target, `SessionDirectory.resolve` **at answer time** (role → current holder via `SessionRoles.holder`); a resolved live target gets the answer via `deliverInboxAnswerFrame` under the `inbox_answer` label, not as a declinable peer message (idle woken, busy queued; planner ruling 2026-11-07); a target resolving to `.inactive`/`.notFound`/`.archived` does **not** drop — set the item `.awaitingDelivery` and keep the answer on the thread. The delivered body re-includes `item.title` + `item.situation` + the chosen option/free text, so a cold recipient can act. `notify` targets get a lighter awareness send. `redeliverAwaitingInbox()` (called when a session appears / on launch) retries `.awaitingDelivery` items and flips them `.answered` once delivered (not `.closed`: closing is final, and the owner may still follow up on a decision it received late).

## Task 4: Timed-veto lifecycle

**Files:**
- Modify: `Sources/IrisKit/InboxStore.swift` (helpers to fetch due veto items) and `Sources/IrisKit/iris.swift` (a `func evaluateInboxVetoExpiries(now:) async` run on launch and on a periodic dispatch tick)
- Test: `Tests/irisTests/InboxVetoTests.swift`

**Interfaces — Consumes:** Task 1 store, Task 3 `submitInboxAnswer`, `UptimeClock`. **Produces:** `func evaluateInboxVetoExpiries(now: Date) async` (idempotent).

Behaviour: for each `.open` `timedVeto` item whose absolute `deadline <= now`: if `emitterTainted` → **auto-hold** (leave `.open`, mark overdue for display, route nothing); else → `recordAnswer` with `vetoDefaultOptionId` and route via `submitInboxAnswer` (the "fires on next launch" catch-up). Idempotent: an already-answered/closed item is skipped, so a second evaluate after a wake does not double-fire. The live in-session countdown uses `UptimeClock` (sleep-aware); the stored absolute `Date` is what launch catch-up compares against.
