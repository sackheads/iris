# Graded delegation

Moved from the feature tour ([docs/features.md](features.md)), word for word (#534).

When the main agent delegates a unit of work, it can hand the subagent a scoped definition-of-done. The finished run is graded by an independent evaluator in a fresh context that never saw the subagent's transcript, so the result carries a trusted verdict ("2/3 met", per-criterion) beside the subagent's own unverified summary — the two are always labeled and never conflated. A grade still running when its work is stopped — the run it belongs to closes, or you stop the conversation that delegated it — is stopped too, its model call cancelled, and comes back as "grading stopped", never as a verdict; a goal whose own final grade is stopped that way is not marked complete. Delegation without criteria behaves exactly as before: no contract, no grade. Either way the subagent works in a goal loop of its own: a turn that ends without `goal_complete` is followed by a reprompt, up to its iteration cap (10 by default, Settings → Agent Limits → Max subagent iterations, separate from the main agent's), and a subagent that reaches the cap without `goal_complete` comes back `failed`, with no summary turn. Each reprompt is a full model round over the subagent's history so far, so a subagent that keeps going costs up to the cap's worth of rounds, each charged to whoever delegated it (in a job run, to the run's budget, which can stop it sooner). Each turn has its own time limit, restarted every turn (15 minutes by default, Settings → Agent Limits → Subagent turn timeout): a turn that runs past it is cancelled and the subagent comes back `timed out`. The pause between turns does not count, and neither does time the Mac spends asleep (#624); time a turn spends waiting on your approval does. There is no separate limit on the whole subagent; the iteration cap times the turn limit bounds it, and in a job run the run's own deadline stops it sooner.
